# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | `punch_in.replace(hour=h, minute=m)` blindly replaces hour and minute on UTC `punch_in` with IST shift times without time zone conversion. | For a 09:30 IST shift, a punch-in at 09:35 IST (04:05 UTC) gets hour replaced to 9, comparing 04:05 with 09:30 UTC and computing negative/bogus minutes. | Convert `punch_in` to IST (UTC+05:30) first, construct shift start on that IST date in IST, truncate to whole seconds, and compare properly. |
| 2 | `compute_late_minutes` (line 37) | `minutes = int((punch_in - start).total_seconds() / 60); return minutes if minutes > 10 else 0`. For 09:40:01, `total_seconds` is 601, `int(10.0166) = 10`, and `10 > 10` evaluates `False`, returning 0. | Punch-in at 09:40:01 IST for a 09:30 shift returns 0 late minutes instead of 10 (Rule R2 specifies late if strictly more than 10:00 elapsed). | Check if `(punch_in - start).total_seconds() > 600`. If true, return `int(total_seconds // 60)` (floor minutes elapsed since shift start). |
| 3 | `compute_work_hours` (lines 40–41) | Uses Python built-in `round(..., 2)` which performs banker's rounding (round half to even) instead of half-up rounding required by R4. | A duration of 2.675 hours rounds to 2.67 instead of 2.68. | Use Python's `Decimal(str(val)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`. Also truncate instants to whole seconds before calculation per R1. |
| 4 | `compute_overtime` (lines 44–47) | Returns `max(0, int((punch_out - end).total_seconds() / 60))` without checking the minimum 30-minute threshold required by R3. | Punch-out 15 minutes after shift end returns 15 overtime minutes instead of 0 (DATA_MODEL.md sample 1 has 5 min past shift end with 0 overtime). | Calculate whole minutes `mins = int((punch_out - end).total_seconds() // 60)`. Return `mins if mins >= 30 else 0`. |
| 5 | `compute_overtime` (lines 44–47) | Overnight shifts span midnight; `end` is set on `date_str` rather than next calendar day, and mixing tz-aware `end` with naive `punch_out` causes `TypeError`. | Overnight shift (22:00–06:00) on 2026-07-06 punches out at 06:40 next day. Starter calculates ~24 hours (1480 min) overtime instead of 40 min, or crashes. | If `shift_end <= shift_start`, add 1 day to the shift end calendar date. Ensure consistent timezone awareness before computing difference. |
| 6 | `create_employee` (lines 78–85) | Concurrency race condition on check-then-insert (`find_one` followed by `insert_one`) without relying on a database unique index. | Simultaneous POST /employees requests with identical `emp_code` can both pass the check and create duplicate records. | Create a unique index on `emp_code` at startup and catch `pymongo.errors.DuplicateKeyError`, returning HTTP 409 Conflict. |
| 7 | `create_employee` (lines 53–61, 78–85) | Missing schema validations (`shift_start != shift_end`, `emp_code` regex `^EMP\d{4,6}$`, email/name lengths), and `created_at` returned as naive datetime instead of epoch ms. | Creating an employee with `shift_start == shift_end` succeeds (201) instead of 422. Response returns datetime object instead of `EpochMillis` integer. | Add Pydantic field validators and regexes; validate `shift_start != shift_end`; store `created_at` in UTC and return integer epoch milliseconds. |
| 8 | `list_employees` (line 93) | Off-by-one pagination bug: `skip = page * page_size`. Since pagination starts at 1 (R10), page 1 skips `1 * 20 = 20` items. | Querying `GET /employees?page=1&page_size=20` skips the first 20 employees and returns employees starting from index 20. | Change to `skip = (page - 1) * page_size`. Add validation `page >= 1` and `1 <= page_size <= 100`. |
| 9 | `list_employees` (line 94) | `total = db.employees.count_documents({})` counts the whole collection regardless of the `department` query filter. | Requesting `GET /employees?department=Sales` returns total count of all company employees instead of matching Sales employees. | Change to `total = db.employees.count_documents(q)`. |
| 10 | `list_employees` (line 95) | Missing required sort by `emp_code` ascending. Results return in arbitrary natural insertion order. | Response order does not match OpenAPI contract requirement ("Sorted by emp_code ascending"). | Add `.sort("emp_code", 1)` to the MongoDB query cursor. |
| 11 | `punch_in` (lines 101, 113) | Crash with HTTP 500 `TypeError` when `emp_code` does not exist (`emp` is `None`, so `emp["shift_start"]` fails). | `POST /attendance/punch-in` with non-existent `emp_code` returns 500 Internal Server Error instead of 404 Not Found. | Check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 12 | `punch_in` (lines 102–103) | Violates Rule R1: uses local server timezone for timestamp, does not truncate to whole seconds, and ignores overnight shifts. | Overnight employee punching in at 05:45 IST on 2026-07-07 gets attendance date "2026-07-07" instead of "2026-07-06". | Parse timestamp in UTC, truncate to whole seconds, convert to IST, and subtract 1 calendar day if overnight shift and time < shift_end. |
| 13 | `punch_in` (lines 104–118) | Concurrency race condition on check-then-insert (`find_one` then `insert_one`) for punch-in. | Two concurrent punch-in requests for the same employee and date both return 201 Created and insert duplicate attendance documents. | Create compound unique index on `(emp_code, date)` at startup and handle `DuplicateKeyError` by raising HTTP 409. |
| 14 | `punch_in` (line 119) | Returns non-standard `"id": str(res.inserted_id)` and unformatted datetime. Contract has no `id` field and requires epoch ms. | Response contains extra `id` field violating OpenAPI `AttendanceRecord` schema; `punch_in` is not epoch ms integer. | Remove `id` from response and serialize `punch_in` (and all instants) as integer epoch milliseconds. |
| 15 | `list_attendance` (lines 144–147) | Severe performance and memory scalability defect: loads entire collection into Python memory (`list(find(q))`) and sorts in Python. | Severe latency, memory exhaustion, or timeout when querying a 100,000-document collection. | Push sorting, skip, and limit directly to MongoDB: `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`. |
| 16 | `list_attendance` (lines 127–143) | Missing date range validation (`date_from > date_to`) and missing secondary sort key `emp_code` ascending for tied dates. | Querying `date_from=2026-07-10&date_to=2026-07-05` returns 200 instead of 422; tied rows returned in non-deterministic order. | Validate `if date_from > date_to: raise HTTPException(422)`. Sort cursor by `[("date", -1), ("emp_code", 1)]`. |
| 17 | `health` (lines 72–74) | Fake readiness probe returning 200 unconditionally without verifying MongoDB connectivity. | `GET /health` returns 200 OK even when MongoDB is offline or disconnected, failing contract requirement ("200 only if MongoDB answers a ping, else 503"). | Ping MongoDB with `client.admin.command('ping')`; catch exception and return HTTP 503 Service Unavailable. |
| 18 | Startup lifecycle | No indexes created at application startup. `DATA_MODEL.md` notes grader seeds collections with no indexes except `_id`. | CRUD duplicate constraints fail under concurrency; queries and explain endpoints execute full collection scans (`COLLSCAN`). | Use FastAPI `lifespan` handler to automatically create all required single and compound indexes idempotently at startup. |

### Examined and confirmed NOT defects:
- **`status` default in `PunchInRequest`**: Defaulting to `"PRESENT"` is explicitly permitted by OpenAPI contract (`default: PRESENT`).
- **Absence of `_id` in API responses**: Attendance records and employees do not expose MongoDB `_id`; they are addressed by business keys (`emp_code`, `date`), which is intentional by design.
- **PyMongo returning UTC/naive datetimes internally**: PyMongo BSON date behavior is expected; converting them to/from integer epoch milliseconds at the API boundary fulfills the contract.
